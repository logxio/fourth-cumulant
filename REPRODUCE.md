# Reproduce the result

Run these commands from this directory with Python 3.10+. Install once with `python3 -m venv .venv` and `.venv/bin/python -m pip install -r requirements.txt`, then use `.venv/bin/python` in place of `python3` in the table. The estimator itself uses only the AIcrowd runtime packages. `manifest.json` records the exact submission file hash and grader package versions. Run `python3 verify.py` directly to check the released numbers, source snapshots and tables. The more extensive `python3 verify.py --full` additionally checks research outputs after rebuilding them with the commands below.

The laptop command runs all three fixed 128 × 16 networks through both live
chains. Each arm uses three single-thread processes, and the two arm stages
run successively. The saved Monte Carlo truth and generated weight hashes are
checked before scoring. One flopscope unit is `2**31` charged FLOPs.
`python3 laptop_exact.py --seed 3` runs a single network in one process;
`python3 verify.py --laptop` reruns all three and checks their numbers.
This is the recorded Apple M5 output; CPU, wall time and RSS vary with load.

## Frozen checks and corrector trajectories

The 122 frozen values in `report/data/frozen_s16/` are included in `data/numbers.csv` and checked by `verify.py`. `make_tables.py 2` includes Table 2b's `fz_e1_` rows; `make_tables.py 3` includes the two frozen columns and C1–C3 as `fz_e2_` rows. `PREREG.sha256` retains the historical hashes; `PORTABLE.sha256` records the portable wrapper and relocated shell recipe. See the frozen directory's README for the exact distinction. The historical timestamp is locally recorded.

After installing the research dependencies and pinned ARC reference, `python3 research/frozen_s16.py rerun` repeats all commands in a new output directory. `python3 research/frozen_s16.py rerun --steps e1_64_8_301 --truth fresh` repeats one small cell. `python3 research/frozen_s16.py compare --out outputs/frozen_s16` compares a rerun with saved final MSEs. No fitting is involved. The saved result includes all three augmented-K=4 runs at width 96 stopped by the memory limit.

`lab/lt_dump.py` regenerates the released estimator's corrector inputs on the public networks; `lab/corpus_lt/` does the same for Keenan Pepper's corpus ([arc-whestbench-p2-d8b-corpus-14k](https://huggingface.co/datasets/keenanpepper/arc-whestbench-p2-d8b-corpus-14k), revision `cc3405a9393bc398e0af4b0e5d6e78da0ad5f6c8`; its shards hold 10⁸-sample per-layer moments, and the weights are rebuilt from seed `770000 + index`). Each trajectory is one single-thread process of about 2 GiB and 35–177 s. Public `data/full_truth.npz` must be obtained separately for the full split. The run behind #336537:

```bash
export OMP_NUM_THREADS=1 V26_STRASSEN=0 AW_DATA=data
python3 -I lab/corpus_lt/fetch.py outputs/shards --count 2048                       # 16 shards, about 32 MB each
python3 lab/lt_dump.py full 0-999 outputs/lt_dump --mem-gb 14                       # and: mini 0-99
python3 -I lab/corpus_lt/corpus_dump.py 0-2047 outputs/shards outputs/lt_dump      # split across workers by index
python3 -I lab/corpus_lt/corpus_prep.py outputs/lt_dump outputs/shards outputs/lt_prep --workers 64
python3 -I lab/lt2_train.py outputs/lt_prep outputs/E32 --ext --emb 32 --hidden 128 --uin --epochs 0 --batch 4 \
    --seq-epochs 30 --seq-lr 2e-3 --e2e-epochs 0 --ntrain 3048                     # one GPU, 37 min on an A40
python3 -I lab/lt2_export.py outputs/E32/lt2_model.pt outputs/E32/lt2_weights.npz
python3 -I lab/lt2_parity.py outputs/E32/lt2_model.pt outputs/E32/lt2_weights.npz outputs/lt_prep mini 0,1
python3 -I lab/lt2_embed.py estimator.py outputs/E32/lt2_weights.npz outputs/E32/estimator.py
```

With `--ntrain 1000` and `lab/lt2_prep.py` on the public dumps alone, the same training command gives #335351's corrector; adding `--seed 1` or `--seed 2` gives the seed check of Section 4.2 (`runs/cloud/lt-seeds/`, about 2 minutes each on one GPU). `lt2_embed.py` replaces only the embedded weights, so the file it writes differs from `estimator.py` only inside `_LT2_BLOB`; the archived run's exact configuration is checked by `research/v13_evidence.py`. These trajectory and training commands are not part of the laptop saved-evidence verification.
